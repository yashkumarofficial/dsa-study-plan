## 💡 Why this exists

DSA is huge. The hardest part is usually not the problems, it is **knowing what to do next** and **not losing your place** halfway through.

This repo is the plan our class study group follows. One page, one clear order, every item numbered. Open it, find the next serial number, solve it, repeat.

It is made to be shared: send the link to a friend and they can see the entire road in a minute.

## 📏 The one rule we follow

> **First we do the basic and easy problems of ALL topics.**
> **Only then do we move to medium and hard.**

That is the whole idea, and it is why the plan is split into two phases:

| | Phase 1: **Basic & Easy** | Phase 2: **Medium & Hard** |
|---|---|---|
| **What** | Learn every topic, then finish its basic and easy problems | Medium, hard and expert problems, plus the extra topic lists |
| **Items** | 313 | 612 |
| **Starts** | Right away | Only after Phase 1 is done for *every* topic |
| **Why** | Understand each topic well before it gets difficult | The hard problems stop being scary once the foundation is set |

Within each phase, chapters go in the same order: language basics, complexity, recursion, linear data structures, non-linear data structures, then algorithms.

## ✨ What is on the page

- 🔢 **S. No. on every item.** Each chapter's list is numbered in solving order, so nobody forgets the sequence.
- 🧭 **Two phases with a sticky switch.** The top bar stays with you while you scroll, so you can flip between Phase 1 and Phase 2 anywhere.
- 📇 **Chapter index.** Each phase begins with a row of chapter chips. Tap one to open that chapter and jump straight to it.
- 🏷️ **Learn and Solve tags.** Every group is marked as something to *study* or something to *code*.
- 🔗 **Every item is a link.** Click a topic or problem to open a GeeksforGeeks search for it.
- 🌙 **Dark, minimal design.** Instrument Serif headings, a warm accent colour, and nothing that gets in the way of reading.
- 📱 **Works on phones.** Made to be opened from a WhatsApp or Telegram link.
- ⚡ **One file.** No build step, no backend, no tracking.

## 🚀 How to use it

1. **Open the live site** and start in **Phase 1**.
2. Open the first chapter. Read the **Learn** lists first.
3. Work down the **Solve** lists in order. The number on the left is the S. No.
4. Click any item to open the matching GeeksforGeeks page, read it, then code it in C++.
5. Finish *every* chapter in Phase 1 before you touch Phase 2.
6. When Phase 1 is done, press **On to Phase 2** and repeat.

**Study group tips**

- Pick a pace together, for example one chapter a week.
- Say the S. No. out loud in the group chat: "I am at Array, 14."
- Compare solutions after solving, not before.
- Re-solving something you got wrong is worth more than starting something new.

## 🏷️ Learn vs Solve tags

Every group of items carries a small tag:

| Tag | Meaning | Examples |
|---|---|---|
| 🔵 **Learn** | A list to study and understand | Language topics, complexity notations, tree types, sorting algorithms, Array prerequisites |
| 🟠 **Solve** | Problems to code | Basic, Easy, Medium, Hard and Expert problem lists |

Both are numbered, because the order matters either way. The tag only tells you whether you are reading or coding.

## 📝 Good to know

- **Links open a search, not a fixed article.** Each item opens a Google search limited to `geeksforgeeks.org`. The right article is normally the first result. We do this because exact article links are easy to get wrong across ~900 items.
- **Some problems appear twice.** The source lists repeat a number of problems across chapters (for example, the Graph medium list and the Graph Algorithms chapter overlap). We kept them so the order stays true to the source.
- **Recursion is our own addition.** The source list for Recursion was empty. We wrote a short one and moved the chapter before the data structures, because trees, graphs and DP lean on it. Edit or remove it if you prefer.
